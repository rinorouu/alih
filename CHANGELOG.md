## [0.2.5] - 2026-09-01

The Operational Foundation release. Alih could already make a verifiable
archive; it could not tell you anything about itself between runs. This release
adds the operational layer around the existing backup pipeline — status,
history, alerting, scheduling, and a browsable view of a recovered archive —
and makes the archive format describe its source in that source's own words.

### Archive compatibility

Read this section before upgrading if you keep archives from an earlier
release.

- **Alih 0.2.5 reads and verifies archives written by 0.2.4** (manifest schema
  2). Such an archive still verifies, re-verifies to the same result, reports
  with its provider correctly named, and can be organized. It is never
  rewritten or upgraded in place. This is tested against archives produced by
  the code at tag v0.2.4, not against fixtures regenerated by the current
  writers.
- **Alih 0.2.5 writes manifest schema 3.** The oldest manifest this build reads
  is a named constant, so dropping a released format later has to be a
  deliberate edit rather than a side effect of a version bump.
- **An Alih older than 0.2.5 will refuse a schema 3 archive.** It reports
  `manifest_integrity` as failed, names the schema version it found and the one
  it supports, and exits non-zero. It does not misread the archive, and the
  archive is not damaged — the older binary simply cannot make claims about a
  format it does not know. Verifying the same archive with 0.2.5 or later
  succeeds. Plan downgrades accordingly.
- An archive whose manifest schema is outside the readable range — older than 2
  or newer than 3 — is refused explicitly and is not interpreted under a schema
  Alih happens to implement.

### Added

- **`alih status`** reports what Alih has recorded about its own operations:
  the last attempt and the stage it reached, the last successful backup, the
  verification result together with whether that archive is still present and
  unchanged, and the connector health and authentication observed at the time.
  Every observation carries its age, and one older than 24 hours is marked
  stale rather than presented as current. Status reads local records only and
  makes no source request; `--refresh` makes exactly one authentication request.
  `--json` prints one stable document on stdout with diagnostics on stderr, and
  the exit code distinguishes healthy, needs-attention, nothing-recorded, and
  unreadable local state without parsing prose.
- **`alih status --reconcile`** reads a backup destination, independently
  verifies every archive it finds, and records what that verification proves.
  It is how backups Alih has no record of become visible again, for example
  after local state was lost or the tool was reinstalled. Which source an
  archive belongs to is read from its own sealed manifest, never from a
  directory name; a preserved `.failed` run is reported but never counted as a
  backup; an older archive never replaces a newer recorded one; and symbolic
  links out of the destination are not followed.
- **Local operational state.** `backup` and `extract` record what a run did in
  a private, user-only file under the user configuration directory: the stage
  reached, whether the run started, failed, or succeeded, the last successful
  backup and where it was written, and the connector health observed at the
  time. A credential is never part of that record. A run whose state cannot be
  written says so and keeps its result — a sealed, verified archive stays
  sealed and verified.
- **A local operational event history.** Each run appends an ordered record of
  the transitions it performed — started, verified, completed, failed,
  connector unhealthy, credential problem — to a bounded private log, so
  another tool can react without parsing command output. Events are ordered by
  position rather than by clock, so a clock moving backwards cannot reorder
  history; a completion is never recorded before the archive it names has been
  verified, reported, and published; and each event type accepts only an
  allowlisted set of fields. `alih status` summarises the history as context
  only — it never decides the reported status.
- **`alih notify`** — explicit opt-in HTTPS webhook notifications for selected
  operational events. Alih reads a private local `notifications.json`, keeps
  secret values in a named environment variable, refuses redirects, and bounds
  payloads, responses, timeouts, attempts, and retry delay. Nothing is sent
  when no configuration exists. `alih notify` checks configuration without any
  egress; `alih notify --test ID` explicitly replays the newest matching
  recorded event. A delivery failure is recorded so `alih status` reports
  attention, but it never mutates an archive, changes a verification result, or
  turns a completed backup into a failed one.
- **`alih schedule`** — native recurring backups without an Alih daemon. A
  strict private `schedules.json` defines daily local-time backups; `preview`
  deterministically renders a systemd user timer, a macOS LaunchAgent, or a
  Windows per-user Task Scheduler definition, while `install` and `remove`
  remain separate explicit actions. Generated files use an absolute executable
  and the existing `alih backup` pipeline and contain no credential value.
- **Overlap protection.** A cross-process OS-handle lock, scoped to connector,
  Workspace, and destination, rejects overlapping runs immediately and records
  an explicit skip rather than a failure or a success. It is released
  automatically if the process crashes, rather than relying on stale PID age.
- **`alih organize --archive PATH --output PATH`** builds an optional
  human-readable browsing view from a canonical archive: a directory per
  Workspace, container, and collection, a Markdown page per record, separately
  copied attachments, and a `provenance.json` index mapping every generated
  file back to its portable identifier, original source identifier, and raw
  evidence path. The archive is independently verified before generation and
  again before publication; `INCOMPLETE`, `FAILED`, and unverified archives are
  refused, and there is no override that could produce a view which looks
  successful. The archive is opened read-only and never modified. The view is
  staged privately and published with one rename, so an interrupted run
  publishes nothing. Regenerating from the same archive produces identical
  content, and generated names stay usable on Linux, macOS, and Windows alike.
- **Connector capabilities and health, where they affect what you can trust.**
  Every capability now carries a stable identity, whether it is required, what
  the connector implements, and what this particular run actually observed — so
  an unsupported capability is no longer indistinguishable from one that
  failed. Health is reported as `HEALTHY`, `DEGRADED`, `UNAVAILABLE`, or the
  explicit no-evidence state `UNKNOWN`, with authentication reported
  separately, so a rejected credential is never presented as a failing provider
  and an unreachable provider is never presented as a credential problem.
  `alih scan` and `alih verify` show each capability with its identity,
  requirement, and availability, and the assessment is carried through raw
  evidence, the manifest, verification, and the recovery report, so the health
  of the run that produced an archive stays readable after it is sealed.
- **`alih scan --json`**, printing the inventory, the capability contract, and
  the operational assessment of one run as a single stable document.
- **`ALIH_SAVE_CREDENTIAL=0`** stops `backup`, `scan`, and `extract` from
  writing an environment-supplied credential to disk, for installations whose
  credential is injected per run from a secret store or that run on ephemeral
  storage. `alih auth` still saves, because that is what the command is for.
- An operator runbook in `OPERATOR.md`, mapping every job involved in running
  Alih on someone else's behalf to the same public commands and local files a
  self-managed user has.
- A hardening traceability matrix in `HARDENING.md`, mapping each operational
  failure scenario Alih must survive to the tests that prove it. The build
  fails if it cites a test that no longer exists or drops a required scenario.

### Changed

- **Archive manifest schema 3.** Entity counts are provider-neutral —
  `containers`, `collections`, `records`, `nested_records` — with the
  connector's own vocabulary recorded beside them as `container:<kind>` and
  `record:<kind>`. Alih reconciles both without interpreting any kind name.
  The manifest also records the connector's display name. See **Archive
  compatibility** above.
- **Raw snapshot schema 2**, carrying the same neutral vocabulary. A schema 1
  snapshot still reproduces its own logical inventory digest exactly, because
  the digest is taken over the vocabulary the snapshot was recorded in.
- A connector no longer has to describe its objects in another provider's
  words. Two rules previously contradicted each other: verification required a
  container's kind to equal its own source type, while the archive writer and
  the reconciler counted only `space`, `folder`, `task`, and `subtask`.
- **The recovery report names the connector that produced the archive.** Nine
  statements previously named ClickUp as a literal, so an archive from another
  connector would have been told its data could be read "without ClickUp". The
  name is taken from the archive itself; an archive written before the manifest
  recorded one falls back to the running build's wiring and then to the
  connector's identifier, never to a placeholder or another provider's name.
- **Provenance records the release that actually produced an artifact.** The
  raw extraction run, the sealed archive and its database, the recovery report,
  and local state now carry the version the build was stamped with instead of a
  `0.0.1` placeholder compiled into the code. A build that stamps nothing
  records `dev`. Archives created by an earlier Alih keep the version they
  recorded; reading or verifying one never rewrites it.
- Verification compares the versioned capability contract recorded in the raw
  evidence against the manifest and rejects an archive claiming a clean result
  while a required capability is unavailable or failed. Archives written before
  the contract remain readable and verifiable unchanged.
- `alih verify` records its result, passing or failing, for an archive Alih
  already has a record of, so a previously verified archive that no longer
  verifies stops being described as proven. An archive Alih has no record of
  never causes state to be invented from a directory name.
- Failed `scan`, `extract`, and `backup` runs print the operational assessment
  alongside the error, using Alih's own bounded wording rather than
  provider-supplied text.
- `alih scan` prints the connector's own hierarchy vocabulary instead of a
  fixed list of ClickUp nouns.
- The documentation now states that `raw/` holds provider responses byte for
  byte, and that those bytes include the short-lived signed attachment URLs
  ClickUp returns. Alih writes no credential of its own into an archive, and a
  signed provider URL never reaches `alih.db`, `manifest.json`, the
  verification result, the Recovery Report, or an organized view; but an
  archive should be treated as being as sensitive as the Workspace it came from.

### Fixed

- A backup no longer fails when it cannot cache a credential it has already
  verified. An installation on read-only or ephemeral storage was losing its
  backup over a convenience it never asked for. Caching is now best-effort for
  `backup`, `scan`, and `extract`, and is reported on stderr.
- `alih organize` now stops on `SIGINT` and `SIGTERM` like the rest of the
  pipeline. It previously ran with a context that could never be cancelled, so
  interrupting a long generation left its staging directory behind.
- `alih scan --json` reported `"connector": "clickup"` as a literal in its
  failure document, so a failure could be attributed to a connector that did
  not produce it. It now reports the connector actually wired.
- Operational health output names the connector it describes. `Connector
  health: HEALTHY` cannot be acted on without knowing whose health it is.
- A comment archived without a JSON body no longer stops an organized view from
  being generated.
- Publication refuses to overwrite anything already at the backup destination.
  POSIX will not rename a directory onto an existing file, but Windows renames
  with replacement and would have deleted a file standing where the bundle was
  about to go. The destination is now checked first, so the refusal is explicit
  and identical on every platform.
- `alih organize` works on macOS. Its path guard rejected a symbolic link
  anywhere above the output, and on macOS `/var` and `/tmp` are links into
  `/private`, so every temporary or scratch location was refused. It now checks
  the directory the view is created in, which is the component a caller's own
  path controls, and still refuses a symlinked output parent or archive.
- `alih organize` works on Windows. Publication flushed the staging directory
  through a directory handle, which Windows refuses with "Access is denied", so
  no view could ever be published there.
- An archived path that is rooted but not absolute — `/etc/passwd` on Windows,
  which names no volume — is no longer treated as a safe relative path.
- Reading operational state while a run writes it no longer fails on Windows.
  Windows will not replace a file another handle has open unless that handle
  allowed it, so `alih status` during a backup could report state as unreadable
  when nothing was wrong — and a process polling status could block the backup's
  own state write indefinitely. State files are now opened so they may still be
  replaced, and the commit additionally waits out brief contention from anything
  else holding the file. A reader still never observes a half-written record.
  POSIX is unaffected and unchanged.
- Test fixtures are marked so Git never rewrites their line endings. Without
  that, a Windows checkout silently added a byte per line to the frozen
  compatibility corpus, and every archive it seals stopped matching its own
  checksums.
- Adapter selection moved out of the core. Normalizers are keyed by the
  connector they declare, and the field interpreter is selected by the
  connector an archive itself records. An archive from a connector this build
  has no interpreter for is still verified, with its field values left unproven
  rather than guessed.

### Internal

Not user-visible, but the reason the changes above can be trusted.

- A frozen backward-compatibility corpus produced by the code at tag v0.2.4,
  with tests proving a current build still verifies, reports, and organizes a
  released archive, refuses one that never deserved to pass, and refuses a
  manifest schema outside the readable range without interpreting it.
- A connector conformance suite driving a deliberately fake adapter through the
  real extraction, archive, verification, report, organize, state, lock, and
  event implementations, so the claim that the pipeline is source-neutral is
  checked by construction rather than by inspection.
- Contract coherence tests asserting where the capability, health, state,
  event, notification, scheduling, and organized-view contracts must mean the
  same thing.
- Structural tests proving what Alih does not do: only seven packages may reach
  the network and each carries its stated reason; exactly one external host is
  compiled in; there is no entitlement check, licence key, or feature flag; and
  the module has one non-standard dependency.
- Property and fuzz coverage for generated path components, attachment
  filenames, relative write paths, the state and event readers, and
  capability-health aggregation, plus process-level tests that send a real
  SIGTERM, SIGINT, and SIGKILL to a real process mid-backup.

## [0.2.4] - 2026-08-31

This is the first release published from the public repository.

### Added

- One-command installers for Linux, WSL, macOS, and Windows amd64.
- Automatic operating-system and architecture selection for the five existing
  release binaries.
- Installer checks for unsupported platforms, download failures, checksum
  mismatches, and preservation of an existing installation on failure.
- First-run workflow guidance in `alih` and `alih --help`.
- `CONTRIBUTING.md`, describing the issue-first process, the principles a
  change must not break, and the checks to run before opening a pull request.
- Continuous integration that runs formatting, `go vet`, the POSIX installer
  test, and the full test suite with the race detector on Linux, Windows, and
  macOS for every push and pull request to `main`.
- Dependabot configuration for Go modules and GitHub Actions, so dependency
  and workflow-action updates arrive as pull requests that CI verifies.

### Changed

- Missing-authentication errors now tell the user to set
  `ALIH_CLICKUP_TOKEN` and run `alih auth`.
- Release installation is now the primary README path; manual installation and
  source builds remain documented.
- The release workflow now validates the installers and publishes them with
  the existing five platform binaries.
- Updated `github.com/mattn/go-sqlite3` from 1.14.49 to 1.14.50.

### Security

- Installers require HTTPS, verify the selected binary against `SHA256SUMS`,
  confirm its reported release version, and stage it before replacing an
  existing installation.
- Installers use user-level destinations and do not silently invoke privilege
  escalation.
- `SECURITY.md`, documenting private vulnerability reporting through GitHub,
  the supported version, what is in and out of scope, and the security
  properties Alih aims to hold.
